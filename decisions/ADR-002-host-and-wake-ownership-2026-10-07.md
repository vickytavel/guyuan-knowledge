# ADR-002 · 宿主与唤醒承载：不强制继承故渊 WakeLoop

Date: 2026-10-07（Asia/Shanghai）  
Status: ACCEPTED（不强制自建/保留 wake loop 的边界）；OPEN（具体框架、组合与接线）  
来源：用户本轮明确：“故渊现在可以不负责wake loop了，之前为虚拟世界做的哪些定时唤醒在新的agent框架下可以不要，用框架本来的东西”，并提醒模拟生活阶段已有框架选型工作。

## Context · 原 OPEN 与问题

当前交接 §4/5 写过“不锁定为新主宿主”“哪些由框架代替”，但没有明确解除故渊自有 WakeLoop 前提；框架资产被压缩为“未定”，淡化了已有选型、比较与离线验证。Checkpoint 4 仅澄清纸面流程，尚未记录本次用户决定。澄清前 current/交接原文保存于 [快照目录](../archive/memory-affect/2026-10-07-host澄清前/)。

## Decision

1. **故渊不必承担自己的 wake loop，也不必继续作为主运行宿主。** 可以由选中的 agent 框架承载模型/工具循环及运行控制，并在能力适用时采用其原生或配套调度、等待、恢复机制。此决定允许替换，不代表已经选择某个框架或完成替换。
2. **旧虚拟世界的定时唤醒不作为新核心要求。** 不把保底心跳、夜间模拟规则、随机世界事件或模拟首次唤醒重新搬进真实活动主链。旧代码、数据、配置与证据保留，未授权删除、迁移或关闭现有服务。
3. **沿已有框架选型证据继续。** 不因当前组合未拍板就从零广搜，也不因旧证据通过就认定已适配新方向；重点复核移除模拟要求后的框架能力和剩余接线成本。

## 术语与责任

- **故渊**是产品及认知/业务规则的归属，不与某个主执行进程、旧 runtime 类绑定。
- **运行宿主**是实际承载会话、agent run、工具调用、任务等待/恢复的框架或组合，具体归属 OPEN。
- Self Ownership 中的 **Host** 指可信的身份/资格检查与 receipt 签发执行侧；可以在所选框架的受控工具、hook 或适配路径中实现。它不特指旧 `runtime/wake_loop.py`，也不要求另建独立服务。
- **Wake** 在 current 中描述“提出重新检查机会”的业务职责，不等于已经选择独立 WakeLoop 组件。底层运行/调度可交框架；来源、主体认领、当前权限、真实完成与通知的规则仍须有人落实，可复用框架机制承载，不能用运行成功替代业务合法性。

## 旧机制与新方向的取舍（源码只读核对）

| 旧机制/新需求 | 当前归属与取舍 | 证据或边界 |
|---|---|---|
| 白天保底心跳，默认每 120 分钟；夜间 23–7 不登记 | 退出新核心默认要求；不替换成同频框架 cron | `core/wake/ringer.py` 的 `should_heartbeat`；`config/world.yaml` 为旧配置 |
| 冷启动登记 `first_wake`，立即且不可中断 | 不继承模拟首次唤醒；新启动初始化/任务恢复按实际需要另定 | `register_cold_start_wake`；启动服务不自动构成主体有话要说 |
| 随机世界事件产生并登记唤醒 | 退出新核心；不换名继续生成虚构经历 | `register_world_events`、`tick`；当前真实证据边界不变 |
| Ringer 常驻 tick 线程 + 旧 WakeQueue 到期检查 | 不要求保留或先抽成通用组件；优先核对选中框架/配套调度是否足够 | `runtime/ringer.py`、`core/wake/queue.py`；线程检查不等于每次都调用模型 |
| 旧 RunSegment 模型/工具循环、wait/idle、串行处理与消息排队 | 可由框架循环、取消、消息处理、定时等待等适用能力承载；不预定旧原语/类名 | `core/wake/run.py`、`runtime/wake_loop.py`、`runtime/api_runtime.py`；旧 `idle(duration)` 是登记未来项，不是必须保留的接口 |
| 用户/主体合法登记的真实时刻、条件、新闻/回复变化 | 功能需求保留，承载方 OPEN；可用框架、配套调度、订阅/webhook 或必要的外部检测适配 | 调度到点不自动知道网站变化，仍需数据接入/条件判断；不为未登记兴趣自动创建任务 |
| 本人任务/子代理进展、结果回传、停机恢复 | 功能需求保留；框架原生能力可承担，核对同一运行恢复与从成果续做的差别 | 现有三候选报告；不要求重复实现已被适用能力覆盖的机制 |
| Affect/Mood 随时间的派生变化 | 保留 anchor + 读时推导；不为刷新数值安排持续模型唤醒 | 第二阶段与 00c；如需阈值检测，其调度策略仍 OPEN |

### 原生能力的层次核对（2026-10-07，仅官方文档）

- [PydanticAI Durable Execution](https://pydantic.dev/docs/ai/capabilities/durable_execution/overview/)将持久执行描述为接入相应 engine；保留同一 run 跨崩溃，与保存对话后继续不同。因此不能由 Core/Harness 有工具循环直接推定已具有常驻定时器/完整调度组合。
- [LangChain cron 官方文档](https://docs.langchain.com/langsmith/cron-jobs)属于 LangSmith Deployment/Agent Server 能力；不能把它写成只装开源 LangGraph 库即可获得的已验证调度。是否采用部署层及资源/运行成本仍 OPEN。
- [Pi 官方 SDK 文档](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/sdk.md)说明 agent session、工具、消息排队、会话存储与取消等；本次未据此证明一套持久定时唤醒服务。该文档由旧 `badlogic/pi-mono` 地址重定向，**现行仓库/文档不能替代旧原型固定版本证据**，没有升级依赖。

这次只有源码与文档核对，没有新框架运行、计时/恢复实验或部署验证。只记录能力所在层，不做新的完整选型排名。

## Why / 替代项

真实活动不需要模拟世界定时自转；已有执行框架可以承担适用的运行机制。把“业务规则仍需落实”误写成“故渊必须自建调度与所有管理器”，会重复建设，也会让旧模拟需求绑架新框架选择。

本次排除的是从旧资料误推“必须先保留/抽取旧 WakeLoop，再把框架接为外部工人”的前提，以及“未最终拍板就从零选型”的阅读误导；它们不是已确认的旧架构决定。两种宿主接法仍可比较，故渊主宿主不作为强制起点。详细旧口径在归档，历史研究/失败证据不改写。

## 影响面与剩余 OPEN

- **第二阶段七组裁决**均不被推翻：运行契约中的 Host 是职责而非旧类名；版本、authority、Affect/Need/时间、消费不授予权限等原则仍有效。
- **三档方案**共享该宿主原则，比较的是需要的处理安排/成本；不要求各档各建一套故渊调度器。框架覆盖的部分从项目自建成本中扣除，外部接入及业务契约保留责任。
- **尚未选定**：主执行框架/组合、主对话与本人任务/子代理承载、所需调度层、登记/撤销/去重/停机补检、真实监听接入、资源预算与 Serein 分工。具体方案仍 CANDIDATE/OPEN，不提前落 schema/API。
- **同步位置**：current 00c/00b/00d、专题 README、第二阶段术语说明、OPEN-QUESTIONS、根/局部 AGENTS 的方向摘要、当前交接、待定问题清单与阶段 checkpoint。
- **下一入口**：用既有三候选证据作针对性职责对照，明确哪层承载新需求、哪些旧机制退出以及真实增补成本，再判断框架组合与运行复杂度。讨论不等于安装、运行验证或实施授权。
