## 3. 组合比较：实际由谁承担

以A2与A1为两列，按同一职责列出最小必要组件、承载层与仍缺的接线：

| 职责 | 必须说明 |
|---|---|
| 主会话与本人任务／子代理 | 模型工具循环、独立工作、并发／等待／取消、结果回流、主对话继续；等待delegate不等于整个进程不能并发 |
| 定时与外部条件 | 注册／撤销／去重／停机补检／检测数据接入由哪层承担；可选框架配套与成熟设施也计入，不恢复模拟心跳或随机世界事件 |
| 受控工具与authority | 谁检查资格／签发receipt、谁执行工具、谁提交认领与成果；A1跨栈由谁归口，不能两边各自宣称完成或授权 |
| 恢复与作品 | session重开、run恢复、从任务／成果继续分别覆盖什么；工具效果未知或回执丢失怎样核对，不把重放当成功 |
| 界面与运行管理 | 主动结果、无文本结束、断线恢复与配置读取各由谁承担；只到职责，不写接口或页面 |
| 维护与部署 | 必须／按需依赖、常驻进程、存储、升级与排障、配置源及桥接；不编内存／工期／费用数字 |

每格区分核心原生、官方可选或部署层、成熟外部配套、项目适配、未验。A1必须指出相对A2及其配套的具体收益，并与双运行时／历史／配置及跨边界恢复成本一并评估；不要求收益只能来自独有功能，也不以Linux退出正常自动支持加入Pi。

在已有三个纸面场景（研究时继续交谈、真实时刻／回复变化、停机后继续创作）中复用已有分析，只补会改变组合判断的差异。

## 4. 可修改性比较：六类实际改动

不是设计万能配置平台。按下表的日常例子，给出A2/A1各自的真实改变路径；对配置优先级、加载与热更新查官方依据，答不了即标未知。

| 改动 | 例子与比较重点 |
|---|---|
| 内容与设定 | 修改世界书条目、表达偏好、提示词或技能说明；内容存放在哪里、谁读取，旧历史会不会继续带入旧指令 |
| 模型与工具参数 | 换模型／provider、调整输出长度、工具超时；不同模型参数支持不同，不能承诺所有开关通用 |
| 调度与预算 | 修改一个登记的查看时间、静默窗口、并发或模型预算；既有登记／正在等候的工作怎样处理 |
| 工具接入与权限 | 配置已存在的工具、撤销文件或网络操作资格；启用已有工具与实现新工具分开，权限变更不能只改提示词 |
| 认知参数与长期设定 | 修改检索／整理参数、投影版本或Calibration；哪些是工程参数，哪些须主体认领／共同确认，历史可比性怎样保持 |
| 流程与结构 | 改本人任务／子代理分工、任务执行逻辑、记忆对象或数据结构；哪些可通过配置组合，哪些要代码／重启／迁移 |

每项回答：使用者改什么；实际生效点（下一请求／下一run／安全边界重新加载／重启等）；对已有session、在途任务、已登记触发和子代理的影响；是否需代码或迁移；由谁校验和留版本／回退记录；框架已有能力与必须增加的适配。只写机制与责任，不给最终字段、配置键、表结构、API或完整状态机。

**不能把“前端保存成功”当“运行中已生效”。** 须指出保存值与当前生效值是否可能不同，以及使用者怎样知道生效范围。并明确每项对旧任务采用旧配置还是新配置的候选策略；不强制所有配置都热更新或立即替换。

继续遵守current authority：设定编辑不等于认领Self Model／确立他人Fact／多方Common Ground；Calibration是慢变、版本化、需主体认领的独立层，不得因界面能写值而成为任意单轮情绪滑块；原始经历／工具回执不随“改设定”静默重写。机制细节仍OPEN，不在本卡替用户裁决。

## 5. 两个变更纸面场景

1. **长任务中改设定和模型**：一个虚构研究任务与一个只读子代理运行时，用户修改表达偏好并切换模型。分别说明主对话下一次请求、子代理当前工作、任务重启后读取什么；旧内容与新设定怎样区别。不可只画“界面→配置→agent”。
2. **撤销工具资格并调整定时查看**：任务在等明天查看虚构论坛，用户撤销写文件资格并修改查看时间。说明既有登记、下一次受控工具调用与已完成效果怎样处理；配置回退是否会重新取得已撤销的权限须单独核对，不能隐含恢复。

这些是纸面推演，不使用个人资料、不运行实验、不冒充配置界面验收。若结论改变authority／生命周期／下一阶段入口，在过程中落入报告与checkpoint，不能只在最终聊天中提及。
