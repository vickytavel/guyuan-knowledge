## 3. 每份的精华（§8 A 类 + §9 要害，压缩）

### 01 记忆本体与数据模型
- 三段式基线：**不可变证据/事件 + 可重算事实 + 带依据的可更新理解**。
- 一张证据**默认多投影**（事实/约定/梗/原则/情绪评价/人物条目），投影多对多，不设单值。
- 「理解不改写过去」的三层保障：证据只增不改 → 新版本+取代边 → 取代带理由与时间。
- 不可变清单：证据、已落事件、已被引用的事实版本、历史理解/约定版本、provenance；其余（抽取结果、聚类、摘要、情绪衰减项、当前事项状态、召回索引）全部可重算。
- 开放问题：事实层与理解层是否同库同表？取代链是否需要传递闭包？

### 02 连续事件线与状态演变
- 双时间戳 + 非删除式失效作事件线骨架；**「重复 / 矛盾 / 无关新事件」三分类**建议全系统统一。
- **一事件多线是常态**，成员关系必须多对多，禁止单值。
- 归线 = 事件共指聚类 + 判断题提纯 + 人工钩子（**宁空勿凑**）；模型产出只作候选。
- 归线/拆线只动派生层、留依据、可整层重算；证据永不改写。
- 时间表示借 Allen 13 区间关系，支持「当时是什么」的时间点查询。

### 03 未完成事项与持续关切
- open-loop 落成**类型化对象**：`kind∈{共同约定/单方许诺/兴趣/任务}` + `trigger{event|time}` + `dueWindow` + `status` + `blocker{owner,action}` + `source_evidence[]`。
- 状态拆三维：生命周期（open/completed/canceled/expired）× 可执行性（actionable/blocked/snoozed/unsupported）× 等待对象（self/other/external-channel）。
- 证据门槛：**显式未来意图语句 + 触发条件或时窗 + 来源原话**，缺一环即降为记忆态（兴趣不升级为承诺）。
- **不得从沉默推断完成**；`resolved/abandoned` 需显式证据。
- 记忆 vs 唤醒：所有变更入记忆；唤醒候选需「未来时点/条件成立 + 可达触发源 + 未取消」；注入默认沉默。
- 最强失败模式：overcommitment（默认 41.7%）、刷动作式假阳性、带工具上下文的注入、敏感检查外发泄漏、blocked 无路径悬空。

### 04 情绪生成与内部状态
- 生成用 **OCC 三分支 + CPM 序贯 SEC**：OCC 定「评什么」，CPM 定「按什么顺序、要哪些输入」。
- 情绪记录必须带 `cause_ref + appraisal_basis`（FAtiMA 已证明可做到），否则答不了「为何产生」。
- 快/慢分层是硬需求：emotion（分）· mood（时~天）· attitude（周~月），各自时间常数与基线；**mood 偏置强度 ≤0.3 且向基线回落**。
- 对具体人的长期态度需独立对象，不被单次情绪覆盖；矛盾情绪需并存（现有实现普遍只会替换）。
- 衰减一律解析式、读时现算、不落库、可整层重算。
- 组合期设**统一「评价变量」接口**（goal_relevance / desirability / praiseworthy / expectedness / coping / norm / attitude_to_object）作为 01/03/06 与情绪模块的唯一契约。
- 旧 25 维的「分层 + 稳态回弹 + 意义权重乘数」可留到设计；**和弦查表与离散互锁不进情绪生成本体**。

### 05 记忆 × 情绪双向耦合（本轮重点）
- **情绪是召回软信号，不是硬门**：语义先选，情绪在排序层加权（emmem 源码 + ENPMR 基准双向佐证）。
- 两个情绪必须分家：编码冻结 `affect annotation` vs 运行时可变 `affect state`；再巩固只动可变层。
- 唤醒→巩固：高唤醒 → 更慢遗忘 + 地板，落成 `consolidation_strength`。
- 态度 = **可重算视图 + 不可变证据链**（双时钟），新态度 invalidate 旧态度而不删，支持「问过去」。
- **salience 自我放大是本专题最大风险**，且有跨专题含义（→07 反馈闭环）。
- 可用基准：HLME(EMU+EQA)、DABench、MADial-Bench、ENPMR-Bench、ES-MemEval/EvoEmo → 作窄验证集。
- 反一致召回：情绪支持场景的 gold 常是**反向**的，必须先定义「一致 vs 调节」策略，不能默认 mood-congruent。

### 06 人物模型、世界书与共同理解
- 四对象 + 归属层级作基线：原话（不可变）/ 派生事实（来源+置信）/ 当前理解与偏好（可修订）/ 共同约定（**须双方确认**），各自带单方-共同归属。
- 偏好演变用**取代而非覆盖**：旧值关区间、留链、默认不召回，仅在「以前/原来」类查询放行。
- 单方 vs 共同是独立一维，不与「分享/私密」混淆；共同基础需「双方确认」事件才升级为准入。
- 注入三档：persona/human 核心块常驻 + `system/` 进 prompt + 世界书 constant/keyword/vector；常驻块与背景世界书分开预算。
- 溯源字段集（PROV 最小集）建议作 01/05/07 公共约定。
- 重要取舍：Mem0 的 ADD-only 与 Graphiti 的取代是两种哲学，「旧偏好保留又不干扰当前」更贴近取代路线。

### 07 整理、召回与运行工程
- 整理必须分级：确定性（去重/聚类/时间戳/哈希幂等）**不调模型** → 模型只产候选 → 待审生效，原文永不改写。
- 召回四层：候选生成（关键词∪向量∪图∪时间，过取 4×、下限 60）→ 门 → 排序（相关×时间×重要×冷却）→ 席位 → 灰区判官（可空选）；**RRF 融合 + 交叉编码器精排 + MMR 去冗余**。
- 情绪/时间/状态一律排序层软加权，解析失败静默降级。
- 反馈三账（进池/上桌/落座）+ 使用自报，是区分「没召回 / 召回错 / 召回了没用」的唯一手段。
- 运行分工：实时（改写+候选+判官）· 收口（落证据+隔离候审）· 夜间（cron 增量派生，幂等）· 批处理（全量重算，dry-run+apply）。
- 成本红线：图数据库、torch/igraph、无门控自动改写判 D；论文时延/token 收益均为**声称**，未复现。
