## 2. 逐候选详表

### 2.1 Kin Mind（`mycyg/kin-mind` @ `b9704b3`，本地 + 本轮实读 E3）

**① 本体怎么分。** Affect 维度与 desire/concern/plan **同库不同表**：`mind_state`(scope, revision, data) 与 `mind_events` 存状态与事件；`mind_contacts`、`mind_action_events` 存联系与行动（本轮实读 E3）。`AffectiveEvent` 带 command ID / agent version / expected revision / evidence IDs / values / reason / origin；同一载荷**可选带 `motivations`（当前只允许 `initiative`/`curiosity` 两键）**。→ 有 Affect / Motivation / Plan 三层，**没有独立的 Attitude 对象**；关系性感受（closeness/flirtation/care/protectiveness/jealousy/possessiveness）**就住在 Affect 维度表里**。→ 与我们第一阶段最实质的分歧点（见 §4-T1、T6）。

**② Affect 底层怎么表示。** 不是 V/VA/VAD，而是**命名维度 + 每维 score/target/baseline/half-life**，0–100 分。`affect_layers.py` 的 `FEELINGS`/`ECHOES` 表可数到 **28 个维度名**（joy, mood, playfulness, expressive_energy, closeness, flirtation, contentment, security, longing, wonder, curiosity, anticipation, sadness, irritability, frustration, grievance, jealousy, possessiveness, worry, care, protectiveness, fear, reassurance, creativity, sharing, initiative, focus, solitude）。**没有 dominance 类维度**。
- 三个派生视图：`undertone`（心境，慢层，τ=24h）、`feeling`（心绪，1–2 词）、`lingering`（余韵）+ `vitals`（虚拟心跳/呼吸，`HEART_RANGE=(50,130)`、`BREATH_RANGE=(8,26)`，明确「a picture…never a measurement」）。
- **D 解决了什么问题？** 在这个系统里 **D 不存在**——它没有用 dominance 解决任何问题，而是用"命名维度 + 每维独立时间常数"替代。

**③ Motivation 怎么工作。** 短期 `Motivation`（`target` 是 **0–100 的数值目标值**，不是愿望对象；另有 half-life、reason）/ desire・wish（对象化信息来自 `content`/`topic`/`kind`，带 strength、过期时间、completion、evidence、可选 concern 关联）/ Concern（kind/target/basis/confidence/evidence + 生命周期）/ Plan（goal/motivation/source/revision/步骤/下次 review）。
- 有 setpoint 吗？**有 target 与 baseline，但没有"隔一段时间自动上涨"的 meter**；短期动力按基线回落，**时间流逝本身不制造动机**。
- deprivation/satiation/frustration？**未见独立三态**；frustration 以维度形式存在于 Affect 表（`frustration` 是一个 affect dimension）。
- Drive/Desire 直接驱动行动吗？**不**。Plan 步骤需宿主回执结算，模型不能自报完成。

**④ Affect × Motivation 怎么耦合。** 两条实读到的边：
1. `AffectiveEvent` 载荷内联 `motivations`（initiative/curiosity）→ 同一事件同时改 Affect 与短期动力；
2. **`curve()`/`_pieces()`：动机未到期时该维度曲线朝 `target` 走；到期后改朝 `baseline`、切换为 `base_half_life_hours` 的节奏**（本轮实读 E3）。→ 这是**我们信息流里没有的第四条边**。
- 阻尼：`echo` 有阈值/半衰期/地板/上限；`undertone` 有 τ=24h 低通 → **天然低通阻尼**。无 `goal_conduciveness`/`frustration` 的显式 appraisal 链（frustration 只是一个维度名）。

**⑤ Runtime 与持久化。** 高度符合我们的原则，且比我们更细：
- 慢层**只在曲线拐点存 anchor**`{m, x, at, fp}`；"reads never write"；历史层「patches two keys deep, so a revision carries only the anchors it moved」→ **部分修订**而非整块覆盖；
- `fingerprint(entry)` 用 digest 标识"这是哪条瞬时曲线"；
- 状态更新在 SQLite 事务中、带 `expected revision`；来源更正/取代/删除 → 相关视图 `needs_review`；
- **没有 tick**：曲线全部读时投影（`state.project`），`affect_layers` 明确不回灌。
- 相对我们的原则，**更好的替代**：把"derived"具体化为"**以 anchor 形式落盘的派生慢层**"（既不每轮存快照，也不每次从头重算）。

**⑥ 表达压缩层。** `feeling`（1–2 词）+ `undertone`（慢层词）+ `lingering`（余韵词）+ `vitals`；`compact()` 产注入块，`coarse=True` 时**脉搏按 5 bpm 取整**，让注入项的 revision 只在语义变化时移动。→ **比我们的 Chord 更具体的一条工程纪律**（表达层的变更粒度对齐），但不构成"更好的压缩方式"本身——它的表达能力弱于 Chord（最多两个词）。

**⑦ 对未决问题的新证据。** 见 §5。要点：**无 dominance；setpoint 以 target+baseline 形式存在但不自动增长；余韵门槛给了"阈值→时长"的经验映射**。

## 4. 对第一阶段结论的挑战（按严重度排序）

**T1（高）· "必须有 Mood 对象"这个先验被动摇。**
第一阶段（01 §2.3、05 §2.4-Q6）把 Mood 当成三档时间尺度里的**一个对象**，只争"标量还是向量"。四候选给出了**三种形态**：
- Kin：**派生慢层**（τ=24h 低通，显式不回灌，anchor 落盘）；
- emotion-system：**根本没有**（逐维 baseline 回落 + 独立 arousal）；
- Drivesoid：**权威持久状态**（base→mood→temperament，由 tick 推进）。
→ C5 的问题应改写为「Mood：对象 / 派生慢层 / 不设」三选一，而不是"标量还是向量"。**派生慢层（Kin 形态）与我们 05 的落盘原则最兼容**，且能同时满足 01 的"快慢分层硬需求"。

**T2（高）· 我们把"余韵"和"长期留痕"压进了同一个触发结构。**
04 §2.4-Q8 的三段式（阈值候选 ∩ 持续门 ∪ 认领覆盖）回答的是**"要不要永久留痕"**。但 Kin 的 `echo` 回答的是另一件事：**"这次变化该在感受上停留多久"**——独立阈值、独立半衰期、独立上限、可丢。emotion-system 的 `EMOTION_FOLLOWUP_GAP`、Drivesoid 的 30 天裁剪，也都在"短期可见 vs 长期留存"之间画了线。
→ 挑战：可能需要**两级**——`echo/余韵`（短期、自动、有上限、不落库）与 `Affect Change Event`（长期、需门槛）。第一阶段把它们合并，会导致"要么不留痕、要么留太多"。

**T3（高）· provenance 的权威位置。**
第一阶段（01 §7.1、03 §7.1）把 provenance 表达为**字段**（`cause_ref`、`appraisal_basis`、`referent_ref`）。DuduLove 的做法是：**"来源可信"是服务端签发的能力对象**，模型可见的只有 `kind/id/messageId/source/…` 白名单，trust 标记**从不接受序列化载荷**。
→ 挑战：只靠"要求模型填 basis"无法阻止**模型自己声明 trusted**。第二阶段若接受 provenance 契约，应明确"**权威由宿主/服务端签发**"，否则我们在 §4.3 里写的护栏（"模型不得自报 provenance"）没有实现形态。

**T4（中）· "禁 tick"红线需要写成可检查的形式。**
Drivesoid 确实在用 `setInterval(tick, 150_000)`（本轮实读 E3）。第一阶段把"禁 tick 累积"写成红线是对的，但表述容易走偏成"禁周期任务"。→ 建议第二阶段改写为一条**可检查的判据**：「任何落盘的状态值必须能由 `(x₀, t₀, 参数)` 闭式重算」——周期任务可以存在，只要它不做增量累加。（Drivesoid 的 `advance()` 是欧拉还是闭式**本轮未读到**，见 §7。）

**T5（中）· Affection × Motivation 缺一条确定性边。**
03 §10 把耦合定为三条边；Kin 的 `_pieces()` 给出第四条：**动机生命周期（到期）直接切换该 Affect 维度的回落目标与节奏**。这条边是确定性的、可重算的、且对"动机结束之后情绪怎么收尾"有直接作用。→ 03 §2.4-Q10 的确定性/模型分工表需要补一行。

**T6（中）· 关系性感受就住在 Affect 表里（Attitude 边界再受压力）。**
第一阶段裁定 Attitude 不是 Affect 运行时状态（01 Q8），C9 我建议采 01。但**两个独立的真实实现**都把 `care` / `jealousy` / `neglect` / `possessiveness` / `closeness` 作为**Affect 维度**（Kin 28 维表里有 closeness/flirtation/care/protectiveness/jealousy/possessiveness；emotion-system 有 warmth/trust/longing/hurt/careUrgency/neglectTrace/jealousyTrace）。
→ 挑战的强度取决于我们说的是哪种东西：**"对某人此刻的关系性感受"（短时）** 与 **"对某人的长期态度"（慢变对象）** 确实是两件事——但真实实现里前者就在情绪表里，**且没有单独分出后者**。DuduLove 提供了反例方向（稳定偏好走 Identity lane）。→ 建议第二阶段把这条拆成两个对象明确定义，而不是一条裁定压两头。

**T7（低）· 我们对"多维"的心理预期可能是错的。**
第一阶段讨论 V/A vs VAD。四家企业级实现的现实是：**命名维度 + 每维独立 baseline/half-life**（Kin ≥28、Drivesoid 15、emotion-system 17）。→ 不是"我们的轴集错了"，而是**轴集可能不是这一层的主要问题**；主要问题是"每维的时间常数与基线从哪来"。

**T8（低）· 综合报告与源码的两处数字不一致**（已在 §0 列出）：Kin "20 维"（实读可数 ≥28 个维度名）、Drivesoid "16 维"（实读 `DIMS` 15 项）。→ 提醒：**筛选报告的 E3 结论方向可信，但计数类细节不应直接引为事实**。

## 5. 对第二阶段四个未决问题的新证据

> 只记机制证据，**不裁决**。

### Q1 · V/A vs VAD

| 候选 | 机制证据 |
|---|---|
| Kin Mind | 不用通用轴集；**命名维度 + 每维 score/target/baseline/half-life**，0–100。`affect_layers.py` 可数到 28 个维度名，**无 dominance** |
| emotion-system | 命名维度 + 逐维 `[baseline, ·, 衰减率, half_life_hours]`；有独立 `arousal` 对象；**无 dominance**；曾有 `energy` 维，被删除 |
| Drivesoid | 15 维命名值（`neutral/tau/peak/amp/width`）；**无 dominance**；arousal 类以 `elation/irritability/fear` 等分散表达 |
| WrenWen | 文档层无 V/VA/VAD 轴集描述；**无 dominance** |

**净证据**：四个实现**没有一个使用 dominance**；也没有一个使用我们意义上的二维通用轴。→ 这一问的**外部证据全部落在"命名维度"一侧**。如果第二阶段要在 V/A vs VAD 之间选，需要注意**候选项目都没有为这两个选项提供支持**——它们提供的是第三种形态。

### Q2 · D 是否保留

| 候选 | 机制证据 |
|---|---|
| 四候选全体 | **没有一家使用 dominance** |
| emotion-system | 有**删除"存在但几乎不动"的维度**的先例：`energy` 实际只在 0.72–0.82 之间动过、且与 arousal 回声 → 1.1 删除，只把 baseline 留在 arousal 项里（本轮实读 E3） |
| Kin Mind | 用 `LEANING=5`（偏离基线 5 分以上才算"倾向"）与 `FEELING_WORDS=(12,25)` 门槛筛掉不动的维度 |

**净证据**：**"维度存在但从不提供独立信息"是可删除的**，而且有人真删过。→ 若第二阶段要裁 D，一个可用的判据是：**D 在实际运行中是否提供与 V/A 独立的信息**；外部没有任何实现认为它提供了。

### Q3 · need / drive 是否应该有 setpoint

| 候选 | 机制证据 |
|---|---|
| Kin Mind | 有 `target`（0–100 数值目标）+ half-life + 过期；**时间流逝本身不制造动机**；生命周期结束只触发"重新考虑" |
| Drivesoid | 每维 `neutral`（回落目标）+ `tau`（2–10h）+ **`DIM_FLOOR`（下限，不是设定值）**；昼夜 `peak/amp/width` 是背景偏置，`CAP=0.08`，且 `jealousy/anxiety/protectiveness/fear` 的 `amp=0`（"只跟事件走"） |
| WrenWen | `stored value = offset from baseline`，lazy decay toward 0；并自述"静息态第一名＝没事时在想什么" |
| emotion-system | 无 Drive；等待状态**必须锚在一条真实未回复消息**上 |

**净证据**：**三家都有 baseline/neutral，没有一家做"无输入自动上涨"的 meter**；最接近"自动增长"的只有 Drivesoid 的昼夜项，而它自己把幅度上限压到 0.08 且部分维度关掉。→ 支持 02 的结论（反对自由增长），并给出 setpoint 的**工程替代形态**：**baseline 是"回落目标/下限"，不是"必须维持的设定值"**——这直接把 02 §4.3 里"心理 need 无客观 setpoint"的风险降级为"可以不做 setpoint，只做回落目标"。

### Q4 · 长期 Affect Change Event 的触发结构 / 参数化

| 候选 | 机制证据 |
|---|---|
| Kin Mind | **余韵双参数**：`ECHO_THRESHOLD=12`（分）→ 半衰期 `1.5h`；`ECHO_KEEP=6` 条、`ECHO_MOVES=4` 条上限；`ECHO_FLOOR=6`、`ECHO_HOURS=6` 硬上限；注释给出"12 分留 1.5 小时、50 分约 4.5 小时"的对照 |
| emotion-system | `EMOTION_FOLLOWUP_GAP=0.05`（|Δ| 门槛）；版本号去重（`careLastTriggeredVersion`/`avoidanceLastTriggeredVersion`）；**实测：33 个真实变化被过严判据拒掉 27 个**；记录按 `messageId:contentHash` 去重 |
| Drivesoid | 概率 30% + 最短间隔 4h（转引 E3）；`HISTORY_DAYS=30` 时间裁剪 |
| WrenWen | Thoughts：半衰期 + 最小强度 + fixation boost + **硬上限 + retire**；Self 转正需"跨不同日期多次见证" |

**净证据**：
1. **四家都用了"幅度阈值 + 时长/上限"的组合，没有一家用"单一阈值即触发"** → 支持 04 的三段式而不支持 01/05 的"任一即触发"；
2. **四家都把"短期可见"与"长期留存"分成两层** → 提示 04 的三段式缺一层 echo（见 T2）；
3. **过严门槛有实测代价**（82% 拒掉率）→ 阈值不能只往上抬，必须有"认领覆盖"通道；
4. 具体数值（12/1.5h/6/6、0.05、30%、30 天、三次转正）**全部是项目自定**，无一可迁移为故渊默认值。
