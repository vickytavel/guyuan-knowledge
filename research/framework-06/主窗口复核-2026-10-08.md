- 归档共 **90 份进程退出记录，90/90 exitCode=0、exitSignal=null**；保存的 stderrTail 未见 Assertion/UV_HANDLE_CLOSING，parseErrors/超时终止均为空或 false。三目录为 23、22、45 份。

## 2. 上游线索与 Windows 版本建议

官方 [Node 24 changelog](https://raw.githubusercontent.com/nodejs/node/main/doc/changelogs/CHANGELOG_V24.md) 的 24.20.0（2026-08-26）段确实列出 [PR #61999](https://github.com/nodejs/node/pull/61999)；该 PR 最终修改为 shutdown 后忽略迟到的延时任务，提供相关 Node/libuv 根因线索。

[Pi issue #9507](https://github.com/earendil-works/pi/issues/9507)症状相似，但写的是 **Pi 0.85.1**，扩展在 `agent_end` 调 `ctx.shutdown()`；本次用 Pi 1.0.4、主动关闭 stdin。Pi版本与触发方式不同，不能称逐项等同的复现；两种触发共用shutdown，见§6补正；issue 不是维护者确认的项目根因结论。未做 Windows 侧复验，不能宣布升级后已修好。

**建议（CANDIDATE）**：后续若做 Windows/Pi 复验，优先选包含该修复的受支持 Node 24.x（24.20.0 或更新的 24.x），钉版并核验；不是所有 Node 主版本的统一 `>=` 保证，不自动升级现有环境。该建议可在交接作为风险/复验入口记录，尚不写成 ACCEPTED ADR 或正式支持矩阵。

同版本 Linux 结果削弱“只因为 Node 小版本不同才不崩”的解释，未单独证明 OS 是唯一变量；驱动语言、扩展/工具负载、续接组等待时间仍不同。Windows 原异常与 Linux 局部无异常两份事实并存。

## 3. 子代理、多会话、并发与沙箱的修正

原补充表拆四种职责有价值，但下述否定过宽，不能作为选型硬前提：

| 原推论 | 复核后的限定 |
|---|---|
| PydanticAI 同进程、父 run 等待 delegate，所以没有同进程并行 | 等待本次工具结果不等于占住整个进程/主对话；[Agent 文档](https://pydantic.dev/docs/ai/core-concepts/agent/)给出 asyncio.gather 并发 run，[Subagents 文档](https://pydantic.dev/docs/ai/harness/subagents/)明确并行委派是独立子 run。旧原型也用了 async Agent.run。业务长任务、重启恢复、CPU/同步阻塞工具与资源隔离仍需明确承载，不必然要多进程 |
| Pi 单会话只投递 active branch，所以同进程只能一个会话 | 这是单 session 的上下文规则，不足以证明多个 SDK session 同进程不能并发；本轮未核验该组合，不作肯定或否定。旧 RPC 原型使用多进程是接法事实，不是所有 SDK 接法的上限 |
| PydanticAI 无 thread 对象，所以无多会话能力 | 缺少内置 thread 管理与显式 history 管理是不同模型，不能说无法维持多段独立对话 |
| 三候选会话不构成 OS 沙箱，所以隔离工具套件只能 Pi 提供 | “session 不等于 OS 沙箱”仍成立；[PydanticAI Harness 官方文档](https://pydantic.dev/docs/ai/harness/)也列出可选 shell/MCP/Code Mode 与 workspace/sandbox。现行文档不等于旧 0.36.0 已验，须核对目标版本/部署条件；不能把未核对的能力算成 A2 必须自建或 Pi 独有 |
| Pi 禁止扩展 timers，所以调度全部在 Pi 外 | [v1.0.4 extensions](https://raw.githubusercontent.com/earendil-works/pi/v1.0.4/packages/coding-agent/docs/extensions.md)禁止的是 factory 中创建长资源，允许 session_start/需要它的工具中创建并在 shutdown 清理；普通 timer 仍不等于持久登记/取消/重启补检服务 |
| 核心库未内置完整调度，所以项目必须自建调度器 | 调度/检测仍需安排，但可由框架配套设施或成熟调度工具承担；三核心库、Agent Server、durable engine 与实际数据接入分层比较。此报告不能升级为“必须自建”的决定，更不能覆盖 ADR-002 |

现行官方并发/沙箱能力只作静态依据，没有补验固定版本。Pi 没有查到完整原生委派服务的结论仍可作有范围的研究判断；关键词零命中本身不是证明不存在所有扩展、第三方组件或可构造能力。
