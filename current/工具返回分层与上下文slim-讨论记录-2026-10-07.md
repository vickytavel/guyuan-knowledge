## 1. 用户关注与当前理解

“工具输入内容区分”按后文“调用结果”理解为工具返回进入模型前的分层；若用户实际指调用参数，需另确认。通用调用参数和 task/权限/凭据等执行元信息同样可区分，但本轮不设计该接口。

A 外置执行只替换隔离任务侧；C 可在故渊宿主下复用生活主会话的模型/工具循环；B 是框架承载主运行。哪些会话用框架、谁持调度与世界结算分开评估。framework-04 只验隔离任务侧，未验生活上下文/工具 slim/最终 Serein 拼接。

## 2. 候选设计（助手建议，待确认）

工具/适配层先把关键事实与大体量材料区分：

| 内容 | 作用 |
|---|---|
| 状态、核心事实、错误/未知与必要限制 | 模型判断需要的信息，规则保留；不能把结果擅自改写为成功或替角色决定 |
| 来源、时间、版本/hash、完整结果引用 | 将精简结果连回确切原文/产物，支持按需读回及本人审阅 |
| 原始正文、详细日志、大段响应 | 在正式任务产物/执行记录中保存；隔离任务材料不自动写成世界经历 |
| 可选预览/本轮详细片段 | 按工具和任务需要进入当前上下文，避免所有原文永久反复携带 |

这不是冻结字段名。工具若是外部返回，可在统一适配层保存原始结果再包装，优先使用官方结果钩子/自定义工具，不默认 fork 上游每个工具。上游已截去的输出无法由适配层恢复，应记录原生截断/缺失。

两类机制分别设计：一类是大结果生成时落盘、只给引用/预览；另一类是近期完整结果保留后，旧轮次在发送请求时按确定性规则 slim。前者不能自动替代现有后者，也不自动将所有工具第一轮强制缩短。读取正文类任务需要足够的实际材料，不能只拿概要冒充完整阅读。

工具 call/result 配对、ID、错误状态、来源、当前执行状态和必要限制保留。模型视图精简与原始证据保存分开；修改历史视图时应处理请求副本，并验证持久记录未被意外删改。框架通用摘要/压缩不默认替代世界工具确定性 slim，是否在隔离任务启用另定。

## 3. 本轮查到的接口（静态，未跑 slim）

- **Pi 1.0.4**：安装包 extensions/types.d.ts 与 [固定版本扩展文档](https://github.com/earendil-works/pi/blob/v1.0.4/packages/coding-agent/docs/extensions.md)有 tool_result、context、context_with_system 和自定义工具 content/details；可包装结果或调整每次模型调用的视图。仅替换 content 而未保留 structuredContent 时会丢该结构字段，接线必须处理其一致性。普通 context 不含系统/工具声明，context_with_system 才覆盖完整 transcript。实际 session 重建还依赖树/活动分支/compaction，不自动知道故渊动态状态与注入规则。
- **PydanticAI Core 2.51.0**：安装源码 capabilities/process_history.py 有 ProcessHistory，通过 before_model_request 处理消息；工具执行 wrap/after hooks 也存在。[官方历史处理说明](https://pydantic.dev/docs/ai/core-concepts/message-history/)可作语义参考，滚动文档不代替固定源码。
- **Harness 0.36.0**：安装包 tool_output_limits 的 README/_capability.py 有 ToolOutputLimits，在 after_tool_execute 处理结果；支持非 LLM 的 Spill/Truncate，也有 Summarize。Spill 保存收到的内容并提供分页读回；不恢复工具上游已丢弃的输出。它按大小处理新结果，不是故渊按轮次/事实字段的完整 slim。[官方能力说明](https://pydantic.dev/docs/ai/harness/tool-output-limits/)为滚动文档，workspace 相关新示例不可直接当固定组合可用。

## 4. 对选型的影响与待验项

Pi 的 session 重建与上下文扩展契合需求，值得作为评价维度；不能仅凭“有上下文重建”宣布比 PydanticAI 更合适。后者同样有请求前历史处理，且有大结果落盘/读回组件。两者具体需要多少 glue、能否稳定恢复原文引用与授权、在 Serein 最终请求中是否出现重复历史，需同场景实测。

建议后续将生活主会话或其可替代执行段纳入范围：注入当前状态不累积旧状态、聊天原话不改写、工具完整结果可查、旧轮 slim 正确保留 call/result 和事实、重开后引用有效、每条实际模型路径都经 Serein。此次不创建或运行新原型、不自动替换 RunSegment、改变压缩默认值或修改现行规格。

现有确定性 slim 代码：[core/wake/slim.py](../../guyuan/core/wake/slim.py)；讨论时的运行覆盖见 [framework-04 复核](../reports/framework-04/主窗口复核与横向比较-2026-10-07.md)，随后 [framework-05 复核](../reports/framework-05/主窗口复核-2026-10-07.md)补了实际请求证据及未验边界。主宿主、框架与结果 schema 仍未定，最新范围见下一节。
