# 故渊 · 窗口上下文持久化与 Checkpoint 约定

> 状态：当前项目级协作规则补充。  
> 适用范围：普通 ChatGPT 窗口、Work、Codex、子代理及其他会话型执行器。  
> 核心原则：**聊天上下文只是运行缓存，项目文件才是 source of truth。**

---

## 1. 为什么需要这份约定

故渊当前同时涉及长期认知连续性、记忆、Affect、Motivation、Self Model、Authority、Wake、Retrieval、Harness 等多个高耦合区域。

任何单个窗口都可能：
- 被压缩上下文；
- 中途切换模型；
- 被关闭或失去早期消息；
- 只读到局部任务材料；
- 在长任务里遗失最初约束。

因此不能把“关键决定、当前状态、下一步”只保存在聊天历史里。

---

## 2. Source of Truth 层级

### 2.1 永久入口

- 根 `AGENTS.md`：项目级协作硬规则。
- 当前主交接：`交接文档-真实活动与记忆驱动.md`。
- 各专题 README / 入口文件：告诉新窗口当前应该先读什么。

### 2.2 当前架构

当前有效的架构理解写入对应专题 current 文件，例如：
- memory-affect-01 / `00c`：整体架构候选框架；
- memory-affect-01 / `00b`：研究参考地图与 OPEN；
- 后续新专题按同样方式建立 current / reference / history 分层。

### 2.3 阶段汇总与任务报告

用于保存：
- 为什么这样裁；
- 证据从哪里来；
- 冲突怎样仲裁；
- 哪些 OPEN 被保留；
- 哪些数值仍待标；
- 哪些只是候选而不是 current。

阶段报告不是自动 current；只有明确吸收到 current 文件后，才成为当前架构的一部分。

### 2.4 交接

交接只回答：
- 现在做到哪；
- 已确认什么；
- 当前最重要的 OPEN 是什么；
- 下一步任务是什么；
- 应读哪些文件。

不要把完整研究正文复制进交接。

---

## 3. 窗口工作规则

### 3.1 开工时

新窗口先恢复文件状态，不依赖聊天历史猜测。

最少读取：
1. 根 `AGENTS.md`；
2. 当前主交接；
3. 本次任务卡；
4. 本专题 current / README；
5. 任务明确要求的阶段报告或参考资料。

如果 current 与历史报告冲突，以 current + 用户最新决定为准；历史保留为证据，不自动复活。

### 3.2 工作过程中

只要出现以下任一情况，就必须在本任务完成前落盘：

- 改变整体架构理解；
- 改变对象边界；
- 改变 authority / capability / permission；
- 改变状态迁移规则；
- 改变 consumer / injection / wake 契约；
- 改变下一阶段入口；
- 一个重要 OPEN 被裁决；
- 一个既有结论被新证据推翻或降级；
- 发现旧配置 / 旧 schema 存在迁移遗漏；
- 外部参考改变 current 设计定位。

不得只在最终聊天回复里宣布。

### 3.3 Checkpoint

长任务不要等“全部做完”才总结。

当任务跨多个阶段时，按自然里程碑写 checkpoint。推荐格式：

```text
Checkpoint N
- 已完成：
- 新裁决：
- 新证据：
- 未解决：
- 已更新文件：
- 下一步：
```

Checkpoint 可以：
- 追加到阶段报告；
- 写入任务卡状态；
- 或在较大任务下建立独立 checkpoint 文件。

不要为每个小动作建文件；只在“继续工作所需的状态发生变化”时写。

### 3.4 上下文压缩后

如果窗口发生上下文压缩：
1. 不凭记忆继续；
2. 重新读最近 checkpoint；
3. 重新读 current 文件受影响章节；
4. 核对本次任务卡；
5. 再继续。

压缩不是设计事件，也不是要求重新总结全项目的理由。

---

## 4. 决策记录格式

重大裁决应保留：

```text
原状态 / OPEN
→ 新证据或用户决定
→ 裁决
→ 理由
→ 替代了什么
→ 影响哪些文件 / 模块
→ 仍未解决什么
```

不要只保留最终一句“Accepted”。

这样未来可以看出：
- 为什么变；
- 是理论证据、源码证据还是用户偏好；
- 是否仍可重开。

---

## 5. 文件职责

### README / 入口
负责：
- 从哪里开始；
- 各文件职责；
- 推荐阅读顺序。

### current / 整体架构
负责：
- 当前已吸收的架构理解；
- 已确认边界；
- 当前仍 OPEN 的关键接口。

不塞完整参考史。

### reference / research map
负责：
- 来源；
- 候选机制；
- E0–E4；
- OPEN；
- 外部项目定位。

### 阶段汇总
负责：
- 推理过程；
- 冲突仲裁；
- 迁移表；
- 参数证据血缘；
- 阶段性 Accepted / Rejected / Open。

### 任务卡
负责：
- 单次范围；
- 禁令；
- 产出；
- 验收；
- 实际执行状态。

### 交接
负责：
- 当前项目状态；
- 最新 5 条更新；
- 下一步。

## 6. Work 与 Codex 的使用分工

当前约定不是产品限制，而是本项目的工作选择：

### 优先用 Work
适合：
- 多文件阅读；
- 调研与综合；
- 架构裁决；
- 生成 / 维护多份项目文档；
- 跨文件长期任务；
- 需要频繁 checkpoint 的工作。

### 优先用 Codex
适合：
- 进入实际代码施工；
- 修改 repo；
- schema / API / migration 实现；
- 测试；
- 代码级重构；
- Harness / runtime 接线；
- 需要持续查看 diff / 调试的工作。

### 当前阶段
当前仍处于：
> **长期认知架构收敛 + Affect/Motivation 运行契约定稿前**

因此优先 Work。

当开始以下事项时切 Codex：
- 最终 schema；
- API；
- 数据迁移；
- 旧 `core/affect/` 替换；
- Authority/Receipt 实现；
- Harness / Wake / Retrieval 接线；
- 测试与回归。

---

## 7. 当前 memory-affect 工作流示例

推荐节奏：

```text
研究 / 压力测试
    ↓
阶段汇总
    ↓
用户裁决 OPEN
    ↓
Checkpoint + 补丁
    ↓
吸收到 00b / 00c
    ↓
轻量 / 平衡 / 完整运行方案
    ↓
选方案
    ↓
再进入 schema / API / implementation
```

任何一步如果改变 current，都应在切换窗口前落盘。

---

## 8. 最重要的一句话

> **窗口可以丢上下文，项目不能丢状态。**

因此：
- 聊天负责思考；
- checkpoint 负责续接；
- current 文件负责真相；
- reference 文件负责证据；
- 交接负责导航。
